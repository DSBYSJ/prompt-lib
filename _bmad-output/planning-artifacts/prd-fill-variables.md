## 一、用户故事

| ID | 作为 | 我希望 | 以便 |
|---|---|---|---|
| US-1 | 我 | 在详情里看到这条提示词要填哪几个空 | 不用自己去找 `{{}}` |
| US-2 | 我 | 边填边看到成品长什么样 | 确认没填错、没漏 |
| US-3 | 我 | 填完一键复制成品 | 粘过去就能发送 |
| US-4 | 我 | 不想填时仍能复制模板 | 不破坏原来的用法 |
| US-5 | 我（手机上） | 表单不被键盘挡住、能滚动 | 通勤路上也能用 |

## 二、功能需求

### FR-1 变量表单（P0）

- 位置：详情抽屉内，正文预览之上。
- 每个变量一个输入框，`label` 就是变量名；同名的多个 `{{}}` **只生成一个输入框**（一次填、全文替换）。
- 无变量的条目**不显示表单区**（现在 24 条都有变量，但自建提示词可能是纯文本）。
- 输入框上方显示"共 N 个变量，已填 M 个"。

### FR-2 实时预览（P0）

- 正文区随输入即时更新：已填的变量显示为**填充值**（高亮底色），未填的保留 `{{变量}}` 原样（高亮描边）。
- 预览用与详情同一块区域，不额外开弹层——避免填的时候看不见上下文。

### FR-3 复制成品（P0）

- 主按钮「复制成品」：把预览里的内容（已替换）写入剪贴板。
- **存在未填变量时不阻塞，但要提示**：按钮上方一行小字"还有 N 处没填，复制后将保留 `{{变量}}`"。
- 复制成功后 toast 文案区分：全部填完 → "已复制成品"；有未填 → "已复制，还有 N 处变量没填"。

### FR-4 复制模板（P1）

- 次按钮「复制模板」：行为与 Epic 1 完全一致，复制 `body` 原文（含 `{{}}`）。
- 保留这个入口是**有意为之**：有人就是要把模板存进别的地方自己改。

### FR-5 清空（P1）

- 表单区右上角「清空」：一键把本条所有填值清掉，回到初始状态。

### FR-6 切换条目即清空填值（P0）

- 关闭抽屉或切到另一条提示词时，上一组的填值**不保留**。
- 理由：变量名相同但语义不同的情况很常见（都叫"主题"），沿用旧值会悄悄填错。

### FR-7 卡片快捷复制保持语义明确（P1）

- 卡片上的复制按钮仍复制**模板**（不能指望卡片上填变量）。
- toast 文案改为"已复制模板 · 打开详情可填变量"，让人知道还有更好的路径。

## 三、非功能需求

| ID | 要求 | 度量 |
|---|---|---|
| NFR-1 | 渲染与判定是纯函数 | `renderTemplate` / `findMissing` 不 import React，可单测 |
| NFR-2 | 替换安全 | 填值含 `$&`、`$1`、`\` 等字符时不得被当作替换模式 |
| NFR-3 | 不新增运行时依赖 | 不引入表单库/状态库 |
| NFR-4 | 不持久化填值 | 不写 localStorage（本期决策，见 architecture） |
| NFR-5 | 移动端 | 底部弹层内表单可滚动，键盘弹出不遮挡当前输入框 |

## 四、验收标准

**AC-1（表单数量）** 给定含 5 个变量的 `study-plan`，当打开详情，那么出现 **5 个**输入框，标题显示"共 5 个变量，已填 0 个"。

**AC-2（同名合并）** 给定正文里 `{{主题}}` 出现 3 次，当打开详情，那么只有 **1 个**输入框，填入后预览中 3 处**全部**替换。

**AC-3（成品复制）** 给定 5 个变量全部填完，当点「复制成品」，那么剪贴板内容**不含** `{{`，且等于预览文本。

**AC-4（部分填写）** 给定只填了 2 个（共 5 个），当点「复制成品」，那么未填的 3 处仍是 `{{变量}}` 原样，并提示"还有 3 处没填"。

**AC-5（空串视为未填）** 给定某个输入框只输入空格，当渲染预览，那么该处仍显示 `{{变量}}`（不会被替换成空白）。

**AC-6（模板复制回归）** 给定任一条，当点「复制模板」，那么剪贴板内容与 `body` **全等**（含 `{{}}`），与 Epic 1 行为一致。

**AC-7（清空）** 给定已填 3 个，当点「清空」，那么 3 个输入框全空、预览回到模板状态。

**AC-8（切条清空）** 给定在 A 条填了值，当关闭抽屉再打开 B 条，那么 B 条的表单是空的。

## 五、边界与失败处理

| 场景 | 期望 |
|---|---|
| 变量名含空格或全角括号 | 变量名原样作为 label，按同名替换；不裁剪用户填值，但判空时 `trim()` |
| 填值里含 `$&` / `$1` | 必须原样输出，不得被当成替换模式（用函数式 replace） |
| 条目无变量 | 不显示表单区，只有「复制全文」按钮 |
| 剪贴板失败 | 与 Epic 1 相同：降级 `execCommand`，再失败提示手选 |
| 变量很多（>8） | 表单区最高 40vh 独立滚动，预览区固定高度不被挤没 |

## 六、对上游三个开放问题的决策

| 问题 | 决策 | 理由 |
|---|---|---|
| 填值放哪 | **Drawer 组件内 `useState`** | 只有抽屉用得到；为它引入 store 或 Context 是过度设计 |
| 空串算未填吗 | **算未填**（`trim()` 后为空即视为空） | 替换成空白会把句子截断成"关于 的作文"，比保留变量更糟 |
| 两个复制按钮怎么摆 | **主按钮「复制成品」+ 次按钮「复制模板」** | 语义不同、都要保留；用视觉层级区分主次，不用一个按钮加开关 |

## 七、不在本期范围

AI 自动填、跨会话记住填值、多套预设、变量类型化 —— 见 brief 第五节，理由不重复。
